# Borrowed from Gradelings (Melvin asked, 2026-11-09)

Part of the decision record. [AGENTS.md](../../AGENTS.md) has the rules that apply to every change and the list of topics. Record decisions about this topic here, in the same change as the code.

Patterns from `mjparinas/gradelings` adopted for Liftsmith. Copy the Gradelings code where it fits rather than rewriting it.

- **Branches and merging:** pull requests go to `staging`; a nightly workflow promotes `staging` to `main` when CI is green (one production build a day). **Agents watch CI on every pull request they open and merge it into `staging` as soon as every check, including "CI passed", is green; when a check fails they find the cause, push a fix and repeat until it merges** (Melvin, 2026-11-09). Agents never merge into `main`; only the nightly promotion does. Flaky tests are fixed at the cause, never retried.
- **Feature flags** defined in code (`src/lib/flags.ts`, built: `flag()`, `cacheFlags()`, a stable per-device `variant()`), state on the server (built 2026-11-10: the admin Flags and A/B Tests tabs and `GET /api/flags/`, see Analytics and the admin panel), cached on the device for offline use, so a feature can be switched off without a store release. A/B tests read through the same path.
- **Admin panel** (`/admin/`, website only, admin emails from the environment, every change audited): built, see "Analytics and the admin panel". Inbox, To Do and System tabs built (see "Analytics and the admin panel"). Still to come from Gradelings: maintenance mode, alerts (emailing admins when a System check goes red), AI-drafted and saved replies in the Inbox, a users list once accounts exist. Test installs are left out of every metric.
- **Error reporting:** Sentry with a scrubber (no workout notes, names or health data leave the device), loaded only when something goes wrong.
- **Analytics:** first-party and cookieless on the public pages (page views and call-to-action clicks to our own database, so visits can be joined to installs and funnels; Vercel Web Analytics runs beside it on the website). In the app, the usage events in `src/lib/analyticsSchema.ts`, with consent rules, disclosed on `/privacy/` and in the store labels. Health data never leaves the device except through sync to the user's own account.
- **Security:** hashed Content Security Policy with no `'unsafe-inline'`, security headers, size-limited request bodies, hashed session tokens, `security.txt`.
- **More engagement, Gradelings-style:** streak freezes computed in `derive`, never stored; mystery crates picked from the session id so every device agrees; a weekly "you got stronger" recap; an "almost there" card ("1 more rep for a bench PR"); shareable milestone cards; seasonal events; a few Easter eggs. Nothing blocks a tap or pushes late-night use.
- **What's new** screen after an update, and **promo, referral and friends-and-family codes** (store promo codes on native).
- **Accessibility:** built, see "Accessibility" under Product decisions.
- **Browser tests like Gradelings':** a full playthrough, an offline run, a layout sweep across phones and tablets, and a tap-latency benchmark ("every tap answers within a frame or two").
- **Store tooling:** scripts that make Play and App Store screenshots and the feature graphic from the real app, plus `docs/PLAY_LISTING.md` and `docs/PLAY_CONSOLE_ANSWERS.md`.
  - **Google Play listing (built, 2026-11-09):** `docs/PLAY_LISTING.md` holds the name ("Liftsmith: Gym Workout Planner"), short and full description, contact details (hello@getliftsmith.com, https://www.getliftsmith.com, privacy at `/privacy/`), screenshot captions and the promo video storyboard. Art is made from the real app, never mocked: `scripts/play-capture.mjs` drives the static build through three and a half weeks of training on a fake clock with a believable sample lifter (some experience, 80 kg, known lifts) and captures raw screens at phone and tablet size; `scripts/play-compose.mjs` frames them with a headline and line in the app's tokens and font (8 phone shots at 1080×1920, 7 tablet shots at 1080×1920 and 1440×2560, and 8 Chromebook shots at 1920×1080 from a 1280×720 laptop-size capture, JPEG) and draws the 1024×500 feature graphic; `scripts/play-video.mjs` turns the same screens into a 31 s 1920×1080 promo video (title card, eight scenes, end card) with ffmpeg. Committed: `store/play/phone`, `tablet-7`, `tablet-10`, `chromebook` and `feature-graphic.png`; the raw screens and the video are rebuilt, not committed (the video goes to YouTube, which is how Play takes it). Listing rules: only features that ship today (no prices or Pro until billing, no watch apps or cloud integrations), no other apps' names, no "best"/"#1", no emoji, every URL with `www`. `src/lib/playListing.test.ts` checks Play's length limits and those rules. The art uses `public/icon.svg` until the new icon is saved as `store/play/icon-512.png`. Re-run the three scripts after a visible change to Today, the workout screen, rest, Recovery, Progress or the finish screen.
- **Email** through Resend (in-app feedback and reminder emails today, see "Reminders and lifecycle messages"; receipts later), with unsubscribe tokens that are never stored and the CASL mailing address.
- **Exercise demos (Melvin approved, 2026-11-09):** a procedural 3D hologram wireframe built with three.js, not filmed videos. Male and female bodies are driven by the same motion, and there are toggles for the skeleton, the target muscles and the bar path. Being procedural, the demos ship inside the app and work offline. Prototype: https://claude.ai/artifact/WrmuLVALnkzLjBPoLcxN8i (source in the project files: `exercise-demos/wireframe-lift-demos.html`).
  - **Shoulders sit below the top of the torso** (`Body.shDrop` in `rig.ts`; Melvin, 2026-11-09: the arms looked attached too high). The joint rides back up, like the shoulder blade lifting, only when a hand needs the reach (hanging from a bar, locking out overhead), so grips stay on the bar.
  - **Every exercise has one** (a test fails if a library exercise has no motion). It shows on the workout screen for the current exercise; the whole demo card is one button, labelled "How to ›", that opens the how-to sheet with the full controls and the muscles worked. There is no separate info icon for it (see "One control, one destination").
  - **3D everywhere; 2D only when the device has no WebGL** (Melvin, 2026-11-09). The 2D version draws the same mesh with the 2D canvas; there is no low-power or user switch to 2D. **WebGL drawn in software counts as no WebGL** (Melvin approved the PageSpeed fixes, 2026-11-10): `src/lib/webgl.ts` reads the renderer name, and SwiftShader, llvmpipe and Windows' Basic Render Driver (no GPU, or a blocklisted one) get the 2D figure, because there every 3D frame is a long task on the main thread. Firefox and Safari report a generic name, which counts as a GPU. The screenshot scripts set `window.__liftsmithForceWebGL` so store art and site screenshots, taken in headless Chromium, keep the 3D figure.
  - **Live heartbeat** (Melvin, 2026-11-09): when a heart rate monitor is connected, a heart on the figure's chest beats at the lifter's live BPM and the BPM shows on the stage. No monitor, no heart. Same on Android, iOS and web, because the BPM comes from the shared Bluetooth heart rate path (`heartRate.ts`).
  - Code: `src/lib/demo/` (rig, body tables, motions, mesh; pure and tested in node) and `src/components/demo/` (`LiftDemo` component, shared loop, WebGL and 2D scenes). three.js is imported only by `scene3d.ts`, loaded on first use, so it stays out of the main bundle (about 136 KB gzipped, cached for offline by the service worker). The inline demo caps at 30 fps and stops drawing when off screen, hidden or covered by a sheet; reduced motion shows a still pose.
  - `LiftDemo` props other screens use: `exerciseId`, `reps` (play that many reps, then stop), `label`, `body`, `view`, `still`, `controls`, `highlight` (muscle weights, for a standing figure), `bpm`, `bodyToggle`.
  - **The figure follows Settings' sex** (Melvin, 2026-11-09): the female figure when the profile says female, the male figure otherwise, including when it isn't set (`bodyFor(profile.sex)` in `LiftDemo.tsx`, passed by every app screen: the workout screen and how-to sheet, the recovery map, the health twin, PR replay and camera rep counting). **The app has no Male / Female toggle and no body label on the figure.** Only the public site's demos (`/exercises/<id>/`, the home page picker) keep the toggle (`bodyToggle`), since visitors have no profile; it isn't remembered. The hero still alternates both figures.
  - **The female figure has athletic proportions** (Melvin, 2026-11-11: the glutes were too big and out of proportion). Her hips are no wider than her chest and shoulders, her glutes stick out no further for her size than the male figure's, and her hip joints sit no wider apart than his (the female shape tables in `src/lib/demo/rig.ts`; `demo.test.ts` checks all three). It's one shared body, so the demos, the recovery map, the health twin and the site hero all change together.
- **Data rights:** JSON export, erase device and delete account; a restore check for backups; a full-storage notice. **Built (2026-11-09):** Settings › Data › Export sets (CSV: every working set, in the lifter's unit, dumbbells marked per hand) and Full backup (JSON: profile, gyms and every event), from `exportData.ts`. On the phone the file goes to the share sheet (`@capacitor/filesystem` plus `@capacitor/share`, Android and iOS), and in the browser it downloads.
- **CSV import** (table stakes, Melvin, 2026-11-09; `src/lib/importCsv.ts`, `ImportCsv.tsx`): Settings › Data › **Import workouts (CSV)** reads exports from **Strong** (comma or semicolon; the unit from a "Weight (kg)" header, otherwise the lifter picks kg or lb), **Hevy** (`weight_kg` or `weight_lbs`, warm-ups, supersets) and Liftsmith's own "Export sets" file. Cardio rows (a distance), Strong's rest-timer rows and empty sets are left out. Names are matched to the library by weighted word overlap, where equipment words fold into our load kinds and words like incline, front or Romanian must match. A sheet lists every name with its match for the lifter to check, and anything unmatched becomes their own custom exercise, with a guessed muscle and load. Workouts are written like hand-logged past workouts (`sessionStart.source: "manual"`, RIR 2 assumed, what was lifted taken as the target), under the active gym. Every id comes from the file, so importing the same file again adds nothing, and workouts dated in the future are skipped. The file is read on the device and never uploaded. Pure web code, so Android, iOS and the web get it together.
- **Body weight log** (table stakes, 2026-11-09): Progress › Body weight logs a weigh-in as a `bodyweight` event (it also becomes the profile's body weight), with a trend line and the change over 4 weeks. It's in the backup. Health Connect / Apple Health weigh-ins can feed the same event later.
- **Languages** (Melvin, 2026-11-09: "i18n and l10n, use as much native as possible"; `src/lib/i18n.ts`, `src/locales/`): English, Spanish and French, then German, Italian and Japanese (Melvin, 2026-11-10: "ensure that all G7 countries are supported"), so every G7 country has its main language.
  - *Which language:* the phone's. On Android and iOS it's read with `@capacitor/device` (`getLanguageTag`), so the system per-app language works: Android 13+ lists Liftsmith under Settings › Apps › Language (`res/xml/locales_config.xml`, `android:localeConfig`), and iOS lists it under Settings › Liftsmith › Language (`CFBundleLocalizations`). In a browser it's `navigator.languages`. **Settings › Language** (Match my phone, English, Español, Français; `profile.language`) overrides it. `<html lang>` follows.
  - *Formatting is the platform's Intl:* numbers (`num`, and `fmtNum` for weights: 82,5 in French and Spanish), dates and times (`date`), relative times (`relative`), lists (`list`) and plurals (`Intl.PluralRules`), all with the phone's full tag (es-MX, en-GB), so regional formats are right even when the text is the base language. **Input boxes and files keep a point** (`plainNum`), and typed commas are read as decimals (`parseNum`, `BumpField`).
  - *Text:* `t(key, vars)` from the catalogues in `src/locales/text/<prefix>.ts`: **one file per key prefix, holding every language** (`"workout.logSet"` is in `text/workout.ts`, English first, then Spanish, French, German, Italian and Japanese), so threads working on different screens never edit the same file (Melvin, 2026-11-09). `src/locales/en.ts`, `es.ts`, `fr.ts`, `de.ts`, `it.ts` and `ja.ts` only gather the files (A to Z); a new prefix is a new file added to all six. English is the source, `{name}` placeholders, plural forms keyed by `Intl.PluralRules` categories. A missing key falls back to English; `i18n.test.ts` fails if a catalogue lacks a key or a placeholder. The translations are a first pass; there will be no separate native-speaker review (Melvin, 2026-11-10), so write every language with care.
  - *Native text:* Android notification channels, the live workout notification's text and buttons, launcher shortcuts and the widget come from `strings.xml` with `values-es`, `values-fr`, `values-de`, `values-it` and `values-ja` (the Wear OS module too). iOS permission prompts come from each language's `<l>.lproj/InfoPlist.strings`. The notification follows the phone's language (on Android 12 and below, the in-app choice doesn't reach it).
  - *German, Italian and Japanese* (added 2026-11-10, every catalogue file, `rmd.*`, Android phone and watch strings, iOS app, widget and watch strings, the Siri phrases): one language list, `LANGS` in `i18n.ts`, kept in step with `MSG_LANGS` (`messageText.ts`), `locales_config.xml`, `CFBundleLocalizations` and the Xcode project's `knownRegions`; `nativeStrings.test.ts` fails when they differ. **Register:** German *du*, Italian *tu*, Japanese polite です・ます (plain だ・である only in the daily quotes). **Fixed terms**, used the same way on every screen: Log set = Satz eintragen / Registra serie / セットを記録; readiness = Bereitschaft / prontezza / コンディション; deload = Deload / scarico / ディロード; recovery map = Erholungskarte / mappa del recupero / 回復マップ; coach's notes = Coach-Notizen / Note del coach / コーチのメモ; gym = Studio / palestra / ジム; rest = Pause / riposo / 休憩; Push, As planned, Go easy = Gas geben, Wie geplant, Locker / Spingi, Come previsto, Leggero / 攻める, 予定どおり, 軽めに; Settings › Workout and › Training = Training and Trainingsplanung / Allenamento and Programmazione / ワークアウト and トレーニング; Health Connect stays its name (ヘルスコネクト in Japanese), Apple Health is Apple Salute in Italian and Apple ヘルスケア in Japanese. **German capitalises nouns,** so a label spliced into a sentence goes through `inSentence()` (`i18n.ts`), which lowercases the first letter in every language but German; never call `toLowerCase()` on catalogue text. **Japanese** has one plural form (`{ other }`), no spaces between words and no italics: the app's font stack adds Hiragino, Noto Sans JP and Yu Gothic under `:lang(ja)` (`globals.css`, `<html lang>` is the app's language), with `line-break: strict` and `word-break: auto-phrase` so lines break between phrases, not inside words. **German** words are long, so `:lang(de)` turns on `hyphens: auto`; check new German labels at the largest text size on a 360 px phone. Exercise names follow each language's gym usage (Kniebeuge, Kreuzheben; squat, stacco; スクワット, デッドリフト), and well-known sayings in the quotes use the language's own version (七転び八起き, Steter Tropfen höhlt den Stein, Chi va piano va sano e va lontano).
  - *Done so far:* the app shell, Today's greeting and start, the whole workout screen, Recovery and the body map, the workout summary, muscle names and recovery bands, the coaching sheets on the workout screen (change the plan, machine settings, the "Why?" sheet's frame) and the remix share button, the setup wizard (gym preset names, prices and the analytics step names stay as they are), the Progress screen and the shared "today / yesterday / 3 days ago" dates, the Gyms screen and equipment names (`EQUIPMENT_LABEL` and the equipment groups, translated on each read; gym preset names stay English), the Awards screen with every achievement's name and goal (`ach.<id>` and `ach.<id>.d`; the English names in `achievements.ts` stay the source, and a test checks they match), weekly quests, level titles, league names (`LEAGUE_LABEL`; `LEAGUES` stays the stable id) and cosmetic names (getters on `COSMETICS`), and the Settings screen, including Calendar, Reminders (the reminder kinds' labels are translated in the screen, because `messages.ts` also runs on the server, which must not import `i18n.ts`'s React hook), Cycle-aware readiness and Extras. Also Workout preferences (and the per-exercise rest, reps and sets editor in the How to sheet), Send feedback, saved routines, and the coach's notes card. The Programs picker, Injuries (body part names, pain ratings, the graded return and the risk sheet; `notAdvice()` replaced the `NOT_ADVICE` constant), and Tools with the TDEE calculator (activity levels and BMI bands are getters, so the public calculator page reads them in English). The one-rep max and DOTS calculators (DOTS bands, confidence and lift names), progress photos, the monthly recap and year in lifting (the share card too; tonnage milestone names in `moments.ts` are getters, so Done and Extras follow), CSV import, and the workout extras: smart plate memory's change line, ghost mode, "Same as last time", and the breathing guide and plate-math game on the rest card. Weekday names and clock times come from Intl (`weekday`, `clockTime` in `i18n.ts`). The glossary, and every coaching reason: Today's "why" lines and the day's call (`why.ts`), readiness signals, the notes on targets from progression, easy and push days, challenges, injuries and plateau fixes, coach's notes (`insights.ts`), the plateau detective's causes and fixes, block week labels, and the "Why?" sheet (`explain.ts`). Notes are worded when the plan is built, so a plan made before a language change keeps its words until it's rebuilt. Also the rest of the workout screen (no workout, all sets done, the end sheet, swaps, set effort, notes and your own exercise), Today (the plan list, the day's call, superset hints, "Why these muscles" and fit around my calendar), the goal-date planner's forecasts and test-day advice (`goals.ts`), what to buy next (`buying.ts`; the plate score reads a `room` flag instead of matching words), shared workout links, the extras cards (moments in `moments.ts`, seasonal challenge names and details as getters in `seasonal.ts`, the strength score band and twins, the buddy check-in message in `buddy.ts`), and the web dashboard (`/me/`: every tab, its charts and past-workout errors in `dashboard.ts`), which follows Settings › Language from the profile it reads; the `/share/` page a friend opens follows their browser's language. Labels kept in engine tables (`MUSCLE_LABEL`, `BANDS`) are translated on each read through `translated()` and getters, so callers stay unchanged. **Finished on 2026-11-10** (Melvin: "yes" to finishing the remaining translations): the exercise library's names, setup lines and cues (`ex.<id>`, `ex.<id>.setup`, `ex.<id>.cue1`…), the general warm-up drills (`warm.*`), earned theme names and unlock lines (`theme.*`), the voice coach's spoken cues (`vc.*`; Android's TextToSpeech and iOS's AVSpeechSynthesizer now get the app's language with each cue, so a Spanish cue gets a Spanish voice even when the phone is in English), the 3D demo's controls (`demo.*`), the plate graphic's words (`plate.*`), PR moments and replay (`pr.*`), the game card on Today (`game.*`), achievement units (`awards.u.*`), the load, reps, plate and superset lines (`fmt.*`), plateau-fix notes, the effort aim under the target, the mid-workout replan's changes, shared-workout notes and the calendar event's title and notes (passed to `CalendarPlugin` on both platforms). Then programs (`pgm.*`: each program's name, credit, summary and steps, and every note the program engine writes on a target), the daily quote (`quote.<n>`, by its place in `QUOTES`; authors and works stay as written, and a test checks the English matches `QUOTES` word for word; Spanish and French use the language's own well-known saying where one exists), and the Health twin's readings (`twin.*` in `twin.ts`: labels, chips, every line and what the plan did). Changing the language rebuilds Today's plan, so its notes follow at once. **Text shared with the website stays English there:** the website must not load the catalogues (`sitePerf.test.ts`), so `exercises.ts` reads translations through a lookup that `i18n.ts` installs (`setExerciseText`), and `LiftDemoCore` and `PlateBar` take their words as a prop (`DEMO_WORDS`, `PLATE_WORDS` keep the English; the app's `LiftDemo` and `app/Plates.tsx` pass the catalogue's). `translations.test.ts` checks each English copy matches its catalogue. Anything that must not depend on the language reads the English (`englishName`): the generator's tie-breaks, so a plan is the same in every language, and CSV import's name matching. Then reminders and emails (`rmd.*`): `messages.ts` and the server's `reminderEmails.ts` read them through `messageText.ts`, which loads only that one catalogue file (the server must not import `i18n.ts`); the phone sends its language with the email subscription (`lang` in the planner's fields, stored with them, so no table change; a subscription without it, from an older app, gets English), and confirmation, welcome and every planned email follow it. The web rest-over notification (`workout.notify.*`). And the iOS app's own Swift text, in `.strings` files that follow the phone's language like Android's `strings.xml`: `App/<l>.lproj/Localizable.strings` (Siri and Shortcuts actions, the rest-over alert and its Log set button), `AppShortcuts.strings` (Siri phrases), and `LiftsmithWidgets/<l>.lproj/Localizable.strings` (the widget, Control Center button and Live Activity); `nativeStrings.test.ts` checks every language has the same keys, the project builds each file, and every Siri phrase has a line. **Still English:** gym preset names, the pages opened from an email link (confirm and unsubscribe), and the website. New UI text goes into its catalogue file (`src/locales/text/<prefix>.ts`) from the start, never as an English string in a component or engine file.
