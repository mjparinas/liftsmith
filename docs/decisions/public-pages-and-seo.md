- **Page speed** (Melvin asked for a PageSpeed Insights review and "execute them all", 2026-11-10). Mobile Lighthouse had the home page at 64 and exercise pages at 65, all from Total Blocking Time (4.9 s and 9.4 s): PageSpeed's test phone has no GPU, so the 3D figure was drawn in software. Text pages were already 98 to 100. The rules now:
  - **3D only on a real GPU.** The hero and the site's demos use `probeWebGL()` (`src/lib/webgl.ts`): software WebGL gets the hero's screenshot, and the exercise page and home page demo get the 2D figure **as a still pose with a Play button** (`autoPlay2d={false}`), since drawing 2D frames is main-thread work too. The app keeps playing 2D on its own.
  - **The hero waits for the page.** three.js is fetched and the figure starts only after `load` and an idle moment (`afterLoad` in `HeroLift.tsx`, at most 2 s), so the text and buttons are ready first.
  - **30 fps and at most 1.5 device pixels** for every demo on the website (`fps`, `maxDpr`; the app keeps 2).
  - **No language catalogues on public pages.** `types.ts` imports `i18n.ts`, which loads every catalogue (all three languages, about 115 KB gzipped). Public client components never import it at run time: `LiftDemoCore` takes `labels`, the pages pass `MUSCLE_NAME`, the hero's script is in `heroProgram.ts` and its plates are worked out on the server (`heroPlates.ts`). The app's `LiftDemo` is `LiftDemoCore` with the translated names. `sitePerf.test.ts` walks the imports and fails if a site component reaches the catalogues again.
  - **Never prefetch the app.** Every `next/link` to `/app/` has `prefetch={false}`; before, every page view downloaded about 350 KB of app code. `sitePerf.test.ts` checks it.
  - **Screenshots at the size shown.** `scripts/site-screenshots.mjs` writes each screenshot full size (780 px) and as a 540 px copy; `Screenshot.tsx` offers both with `srcSet`. Image optimisation stays off (the static export needs it off, and Vercel's is metered).
  - **The app's first screen is measurable:** the `rise` animation starts at opacity 0.01, not 0, because Chrome doesn't count a paint at opacity 0 as the largest contentful paint and PageSpeed reported an error for `/app/`.
  - After the change, local Lighthouse (mobile / desktop): home 90 / 100, exercise page 92 / 100, compare 99 / 100, app 84 / 100, blog 99. Next's own 14 KB of polyfills (`Array.prototype.at` and friends) are built in and stay.

- **Bing and IndexNow** (Melvin, 2026-11-10: "Add Bing"). The site is verified in **Bing Webmaster Tools** by importing it from Google Search Console (no meta tag or file needed; the import also brings the sitemap), so Bing reads the same `/sitemap.xml`. **IndexNow** tells Bing, Yandex, Seznam, Naver and Yep about new and changed pages without waiting for a crawl: the key is `INDEXNOW_KEY` in `src/lib/indexnow.ts` and is served as `public/<key>.txt` (not a secret; IndexNow fetches it from our host to trust the pings). The daily admin job (`/api/cron/admin/`, 13:00 UTC, after the nightly 09:00 promotion) calls `pingIndexNow` (`src/server/indexnow.ts`): every sitemap page that's new, or whose date changed, since the last ping goes to `api.indexnow.org` in one request, and what was sent is kept in `indexnow_sent`, so the first run sends every page once and later runs send only new posts and pages and edited articles. Pages without a date (exercise pages, say) go again only if their address is new; Bing recrawls them from the sitemap. Only production pings (`VERCEL_ENV=production`). A refusal is kept for the next day, and the job's result shows `indexNow: { sent }`. Changing the key means a new file in `public/` and the constant in the same change. **Public profiles go too** (Melvin, 2026-11-12: "Do the Bing thing"): `peopleRoutes` turns the people sitemap into routes dated by each profile's last workout posted for everyone, so a profile is sent when it turns public and again after each new public workout. A profile that was sent and has since gone private, been suspended or changed handle is sent once more (signature `gone`), so the engines recrawl it, find the noindex "isn't public" page and drop it.

- **On-page fixes (2026-11-11, batch 1):**
  - *One metadata helper.* Every public page builds its metadata with `pageMeta()` (`src/lib/pageMeta.ts`): title, description, canonical, Open Graph (site name, type, address, image) and a `summary_large_image` X card. Next replaces a parent's `openGraph` rather than merging, so each page sets all of it; the root layout keeps a default image for anything else. The layout also allows `max-image-preview:large` and full snippets, for Google Discover.
  - *Preview cards.* Every page has a 1200×630 card under `public/og/` with the page's title and the app's own 3D figure: one per exercise (shared with its alternatives page), muscle (shared with its muscle + equipment pages), equipment item, article, comparison and tool, and `default.jpg` for the rest (about 420 cards for 800 pages).   - *Exercise stills.* Search engines can't see the WebGL demo, so each exercise page also shows a still of the figure mid-rep with the working muscles lit (`public/stills/<id>.webp`, 320 px, from the same script) under "Muscles worked", with alt text, and lists it and the card as the `HowTo` image.
