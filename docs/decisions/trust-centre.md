# Trust centre (Melvin, 2026-11-10: "add a trust centre similar to Gradelings")

Part of the decision record. [AGENTS.md](../../AGENTS.md) has the rules that apply to every change and the list of topics. Record decisions about this topic here, in the same change as the code.

- **`/trust/`** (`src/app/trust/page.tsx`, `TRUST_GROUPS` in `src/components/site/TrustCentre.tsx`), laid out like Gradelings' `/trust/`: groups of controls (Privacy, Health data, Accounts, Coaching, Payments, Infrastructure, Email and AI, Operations), one short line each with a shield, a "Last checked" date (`TRUST_UPDATED`), links to `/privacy/` and `/delete-account/`, and a "Report a security problem" section. High level, not verbose: a note stays under 90 characters (`trust.test.tsx`).
- **Claim only what ships.** Every line was checked against the code on 2026-11-10 (offline-first event log, optional account, usage stats off by default in the EU/EEA/UK/Switzerland, cookieless site counting with Global Privacy Control, Health Connect Limited Use, on-device rep counting, backup exclusion, hashed session tokens, email code try limits, RevenueCat and the stores for payment, the webhook's shared secret, security headers and the script policy, self-hosted code, database rate limits, Resend's SPF and DKIM records, DMARC (`_dmarc` TXT `v=DMARC1; p=quarantine; adkim=r; aspf=r`, added by Melvin in Cloudflare on 2026-11-10, with no `rua` because he found the reports too noisy), synced data in Turso, AI drafts with human replies, admin two-step sign-in and audit log, the admin panel showing only counts of synced data, CI tests and `npm audit`, the 2026-11-09 security audit, and UptimeRobot watching `/api/health/`, which the admin System tab reads with `UPTIMEROBOT_API_KEY`). Something still being built can be listed with `status: "progress"`; anything we don't do is left out rather than softened. Health data is described as "only what you allow", not "read-only", because the app writes a finished workout's calories and heart rate back.
