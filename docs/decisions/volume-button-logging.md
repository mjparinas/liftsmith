# Volume button logs a set (Melvin, 2026-11-12)

Melvin picked "earbud button logs a set" from the list of new connections, then chose the **volume button** over play/pause on the decision card: play/pause belongs to whatever app is playing music, so taking it would stop the music, and on iOS an app only gets play/pause while it's the one playing.

- **A lab** (`labVolumeLog`, off by default, Settings › Labs › Volume button logs a set; Pro like every lab). It's marked `native`, so it shows only in the Android and iOS apps: browsers don't hand volume keys to pages.
- **What a press does:** volume up on the phone or on Bluetooth earbuds or headphones does what Log set does (the set as planned, with the same sound, haptic and burst). Pressed during rest, the rest ends and the next set is logged, the same as voice logging treats a set said during rest. Undo puts it back. Presses closer than 700 ms are one press (`PRESS_GAP_MS`), because a held key or a Bluetooth volume change can arrive twice.
- **The volume never moves.** The press is caught and the volume goes straight back, so music keeps playing at the same level. Volume down still turns it down, so the lifter can always lower the music.
- **Only while the workout is on screen** and nothing covers it (a sheet, the swap list, the end dialog), not on cardio and not once the workout is finished. Android doesn't give an app volume keys from the background, and the web view's code is paused there on both phones. With the screen locked, Log set on the lock-screen notification or Live Activity is the way in.
- **How each phone does it** (`src/lib/volumeKeys.ts`, `workout/VolumeLog.tsx`):
  - *Android* (`VolumeKeysPlugin.java`): `MainActivity.dispatchKeyEvent` takes the phone's own volume up key, and a `ContentObserver` on the system settings watches the music volume, which is how earbuds change it over Bluetooth (absolute volume); a rise is a press and the volume is set back. Stops in `onPause`, starts again in `onResume`.
  - *iOS* (`VolumeKeysPlugin.swift`): iOS gives apps no volume key events, so it watches the audio session's `outputVolume`, which the phone's buttons and earbuds both change, and sets it back through a hidden `MPVolumeView` slider (in the view tree but out of sight, which also keeps the system volume pop-up away). The session is `.ambient` with `.mixWithOthers` if nothing else set a category, so other apps' music keeps playing. It's started again for each set, because the voice coach and voice set logging end the session after they speak or listen.
  - At full volume a press can't raise it, so nothing would be seen: both phones lower the volume one step when they start listening.
- **Not yet tried on a phone** (2026-11-12): on Android, check that earbuds' volume up is caught (most use absolute volume, which changes the music volume; a few don't) and that the phone's own key logs once. The iPhone check is in [Open items](open-items.md).
- **Not built yet:** a setting for which button (volume down, or a long press). Volume up is the one most earbuds have as a single tap.
