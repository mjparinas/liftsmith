# Workout generator on the website

**Asked:** Melvin, 2026-11-27 (traffic idea 1: "do them all, put effort into them"). A free workout generator on www.getliftsmith.com that people find through "workout generator" searches: the visitor picks equipment, minutes and what to train, the real adaptive engine writes a workout with sets, reps, rest and a short reason for each choice, every result has its own link, and "Start in the app" opens it in the app.

## What it is

- `/tools/workout-generator/` in English and `/<lang>/tools/workout-generator/` in the other nine languages (one of the translated tools, `LOCAL_TOOL_SLUGS`, `LocalToolView.tsx`). First entry on the tools index, the site footer's tools column and the home page's tools list.
- Choices: equipment (four presets, Full gym, Home gym, Dumbbells only and No equipment, or Choose equipment with the app's own equipment groups as chips, cardio left out), minutes (15 to 90 in 5s, a slider), what to train (full body, upper, lower, push, pull, legs, chest, back, shoulders, arms, glutes, core), goal (muscle, strength, fitness), experience (new, some, experienced) and a Pair exercises into supersets switch. No typing.
- The workout: each exercise links to its guide (the translated one where it exists), with sets × reps (or × seconds for holds and carries), rest, reps in the tank (holds and carries say "stop when form slips" instead; never rep wording on a timed set, AGENTS.md Action over stats), warm-up sets, the superset letter and its reason. When the equipment and area can't fill the time it says so ("About N minutes is all…") instead of padding.
- **Every choice has a reason** (Action over stats), built from the same data that picked it: why this exercise (first big compound while fresh, compound, smaller finisher, bodyweight compound, hold or carry, naming the muscle), why this rep range (by goal), why this many sets (a main lift, or using the time) and, on the first of a pair, which exercise it pairs with and why the rest is shorter. Whole catalogue lines with placeholders, never glued English.
- Buttons: **Start in the app**, **Another workout** (same choices, next seed) and **Share this workout** (the phone's share sheet, else copy the link).

## How it works

- **The engine runs on the server**, never in the browser: the engine and the 730 KB English catalogue it pulls in would make the page heavy. `GET /api/workout-generator/?w=<code>&lang=<lang>` (`route.api.ts`, server build only) returns the drawn view (`genView` in `src/lib/webWorkoutView.ts`). No account, no database read or write, nothing stored; answers are cached by the CDN (`s-maxage` a day) because the same code always gives the same workout. A bad code is a 400.
- **The page is drawn at build time with an example** (the defaults: full gym, full body, 45 minutes, muscle, some experience), so search engines and the static export see a real workout with reasons; the component (`WorkoutGenerator.tsx`, type imports only) fetches a new one on every change (slider and equipment debounced) and writes `?w=<code>` into the address with `replaceState`. On a phone, a "See your workout" pill appears when the result is below the fold after a change.
- **Same link, same workout.** `generateWeb` (`src/lib/webWorkout.ts`) builds a profile and gym from the choices and calls the app's own `generate()` on a fixed day (`GEN_DAY`) with the seed in the gym id, so the seeded draw repeats. Fresh lifter, no history, first week of a block, never a deload. The automatic superset option is the app's `training.supersets`.
- **The code** is `1.<equipment mask, base 36>.<minutes>.<focus>.<goal>.<level>.<pairs 0|1>.<seed, base 36>`. `decodeGen` refuses anything that doesn't re-encode to itself, so junk never crashes and never draws. The page also reads plain query parameters (`eq`, `min`, `focus`, `goal`, `level`, `pairs`, `seed`), dropping what it doesn't know.
- **Start in the app:** Android's verified App Links already claim `/tools/`; `hashFromLink` maps `/tools/workout-generator/?w=<code>` (any language) to `generatorHash(code)` (`src/lib/genLink.ts`), which draws the same workout on the phone and opens it as a shared routine (`#/routine/<code>`, the Add routine screen), and a bad or missing code opens Today. Because Chrome on Android won't leave the browser for a link on the same site, the button on Android is an `intent://` link to the generator link with `package=com.getliftsmith.app` and the web app as the fallback. Everywhere else it opens the same routine in the web app (`appUrl`, `/app/#/routine/<code>`). Weights are left out: the app fills them in on the first set, like any shared routine.
- **iOS** has no Universal Links yet (deferred, [Platform deltas](platform-deltas.md)), so on an iPhone Start in the app opens the web app with the routine; the iPhone app takes the same link through Routines › Add a routine from a link.

## Words

- The page (title, description, intro, FAQ, How the workout is built, further reading) and the controls are in `src/locales/site/tools/gen/<lang>.ts` (`GenUi`, `ToolPageText`); the workout's title and the focus names are app lines (`gen.*`, `src/locales/text/gen.ts`), read on the server by `genWords` in `fromApp.ts`; exercise names come from the exercise catalogue.
- `webWorkout.test.ts` checks the code round-trip (fast-check, seeded), junk, the query, determinism, that every exercise fits the equipment and area and the workout fits the time, every preset × area draws something, supersets, every reason filled and timed sets in seconds, the translated title, the short note, the app link drawing the same exercises and sets, and the Android link.
