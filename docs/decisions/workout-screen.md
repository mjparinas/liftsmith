# Workout screen

Part of the decision record. [AGENTS.md](../../AGENTS.md) has the rules that apply to every change and the list of topics. Record decisions about this topic here, in the same change as the code.

- Big target weight and reps with steppers, the barbell plate graphic for every barbell set, a big Log set button, an automatic rest timer with +30 s and Skip, and the next set's plates shown during rest so the lifter can load while resting.
- **Live workout notification and lock-screen rest timer.** On Android, a foreground service shows an ongoing notification with a live countdown, the next set and plates, heart rate, and Log set and +30 s buttons; it sounds and vibrates when rest ends. On iOS the same content is a Live Activity on the lock screen and in the Dynamic Island. The web build falls back to a service-worker notification and an alert at rest end (`sessionNotify.ts`).
- The screen stays on during a workout (wake lock), unless the lifter turns it off in Workout preferences.
- **Workout preferences** (Melvin, 2026-11-09; Settings › Workout preferences, `#/training`, `TrainingSettings.tsx`, `src/lib/training.ts`, stored on `profile.training`). Every field is optional and missing means the automatic choice, so older profiles behave exactly as before. Everything is chips and taps (no typing), so it works one-handed in the gym.
  - *Rest between sets:* a default for big lifts and one for smaller lifts, plus a per-exercise time. Order: the exercise's own, then compound/isolation, then by goal (`restFor`).
  - *Rep ranges:* one for compound and one for isolation lifts, plus a per-exercise range (`repRange`). Type ranges apply to loaded exercises only (bodyweight work keeps adding reps); holds stay in seconds. Double progression runs inside the chosen range.
  - *Sets per exercise:* Auto (3, 4 on the first big lifts, a filler set when time allows) or a fixed 2–6, plus a per-exercise count. A chosen count gets no filler sets; deload weeks and easy days still use fewer.
  - *Effort scale:* RIR or RPE (RPE = 10 − RIR, RIR 4+ shows as RPE ≤6). Stored as RIR either way; only the labels change (Today's week chip, the aim under the numbers, the optional set-effort row).
  - *Rest timer:* auto-start on (default) or off. Off leaves a **Start rest** button after Log set; the rest still counts from Log set. Rest-over alert: follow Sounds and Vibration (default), both, sound only, vibration only, or silent; it drives the in-app chime and buzz, the native alert and the web notification. Keep screen on (default on).
  - *Favourites:* a star in the exercise's How to sheet, or picked by muscle in Workout preferences. The generator weights a favourite 6× and prefers it over keeping last time's exercise when both fit; it still needs the gym's equipment, recovery and the day's muscles.
  - *Muscle priorities:* up to three. They aim for a third more weekly sets (`PRIORITY_VOLUME`), rank higher when recovered, and get leftover-time sets first. Recovery rules are unchanged, so a fatigued priority muscle still waits.
  - *Default workout length:* the Today slider goes back to it on the first open of each day (`minutesForToday`, `profile.minutesDay`); "Last used" keeps the old behaviour.
  - *Week starts on:* Monday (default) or Sunday, for streaks, freezes, quests, recaps, weekly stats and the web dashboard's calendars. `derive.ts` holds it as module state set from the profile (`setWeekStart`, `weekOf`, which replaced `mondayOf`). Training blocks keep their own 7-day weeks from `blockStart`.
  - *kg or lb:* Settings › Units is the display unit. Each gym also switches its plates between kg and lb (Gym › "This gym's plates are in"), which swaps the kit for a standard set in the new unit, because plates don't convert. When the gym's unit differs from the display unit, the workout shows the weight in both.
  - Per-exercise rest, reps and sets are also editable from the How to sheet during a workout; they apply from the next plan.
- **Supersets** (table stakes, Melvin, 2026-11-09; `src/lib/superset.ts`). A chain button between two exercises links them, on Today's plan and in the workout's "Coming up" list; tapping it again splits them, and three or more can be chained. Linked exercises share `PlanItem.group` and alternate: one set of each with a 15 s switch (`SWITCH_REST`), then the longest of their rests before the next round; when one runs out of sets the other carries on with its own rest. Warm-ups run the first time each exercise comes up. Plan length counts one rest per round, so linking shortens the estimate. Each set event records its `superset`, so "Same as last time" brings the pairing back. Links made on Today survive a rebuild of the plan (length, call) while both exercises are still neighbours, and so does splitting a pair the plan linked itself (a routine or "Same as last time"): the store keeps `a>b` for a link and `!a>b` for a split (`applyLinks`). **Pairing has to show** (Melvin, 2026-11-09: "the pairing of supersets doesn't do anything"; the link worked underneath but was easy to miss): on Today the link button sits on the line between the two exercises it joins (filled blue when linked), linked rows share a tint, a dashed join and one accent bracket down the left, each says "Superset A · 1 of 2", and the hint under the list says they alternate and how many minutes it saves. During the workout the superset chip has a "Then <exercise>" line naming where the next set goes. The generator never pairs exercises by itself yet. Pure web code, so Android, iOS and the web get it together.
- **Saved routines** (table stakes, Melvin, 2026-11-09; `src/lib/routines.ts`, `Routines.tsx`). The lifter's own list of exercises, set counts and supersets, used instead of the adaptive plan for a day. Today's **Routines** chip opens the list: Use today (the chip then shows the routine's name, and "Back to today's adaptive plan" undoes it), edit, delete, **Save today's plan as a routine**, or **Build a new routine** from the exercise library (search by name or muscle; what the gym can do comes first). The summary has **Save as a routine**, which takes what was actually done, swaps and supersets included. Weights and reps still come from progression and warm-ups from `warmup.ts`, so a routine keeps moving forward; exercises the gym can't do are left out for that day. Custom exercises can go in a routine (the lifter chose them, unlike the generator). Routines live on the profile (`profile.routines`, newest first, at most 50 of 20 exercises each), so they're in the backup and will sync with the profile; `sessionStart.routine` records which one a workout came from. Free, like the logger. The length slider doesn't change a routine. When the programs work (`Profile.planSource`) lands, a routine becomes `{ kind: "routine", id }` there. Pure web code, so Android, iOS and the web get it together.
- **Notes, set effort and custom exercises** (table stakes, Melvin, 2026-11-09). Each is its own event (`note`, `effort`, `customExercise`), so it syncs and exports like everything else.
  - *Notes:* written in the exercise's info sheet (500 characters at most). The latest note on an exercise shows under its name every time it comes up, in any workout.
  - *Set effort:* during rest, an optional "Reps left in the tank on that set?" row (0 to 4+) for the set just logged; it never adds a tap during a set and disappears once answered. In `progression.ts` (`effortSignal`), sets that had 2+ more reps left than planned count like "too easy", and sets closer to failure than planned count like "too hard". Explicit post-exercise feedback wins when both exist.
  - *Custom exercises:* "+ Add your own exercise" at the bottom of the swap sheet (name, main muscle, equipment, whether it's a big lift), then it's used straight away. They're registered into the library on load (`registerCustom` in `exercises.ts`), get starting weights, progression, recovery and stats like any other lift, but **the generator never plans them**, because we can't know their movement well enough to programme them.
