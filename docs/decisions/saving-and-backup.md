# Saving and backup (Melvin, 2026-11-09; built)

Part of the decision record. [AGENTS.md](../../AGENTS.md) has the rules that apply to every change and the list of topics. Record decisions about this topic here, in the same change as the code.

- **Everything is saved on the device as it happens, and an account is optional.** Setup's "Save your progress" step and **Settings › Saving and backup** (`Saving.tsx`, `src/lib/saving.ts`) say where the data lives on this platform and, in a browser, what can erase it (clearing site data, a private window, and on iPhone Safari's 7-day rule for sites not on the home screen). The setup step shows the sign-in buttons (`AccountPanel`, see "Accounts and sign-in"); Saving and backup links to Account and sync; once signed in both say the data is backed up to the account, and Today's browser nudge stays away.
- **Browser:** **Add to home screen** opens the browser's own install sheet where there is one (`beforeinstallprompt`, Chrome and Edge), otherwise it shows the steps (Safari: Share › Add to Home Screen). The app asks the browser to keep its storage (`navigator.storage.persist()`) when setup ends, on each open and after an install. Today shows one dismissible "Saved in this browser only" note after the first workout, browser tab only. Store links appear beside it once `STORE_LINKS` are set.
- **Backup and restore** (all platforms): Save a backup file (the full JSON backup moved here from Data) and **Restore a backup** (`src/lib/backup.ts`). Restoring adds and never deletes: events are kept by id (restoring twice adds nothing), the backup's gyms replace gyms with the same id, and the backup's profile comes back. With an account, sync moves it instead; a backup file still works without one. Pure web code, so Android, iOS and the web get it together.
- **Accounts with sync** landed after this (2026-11-09): the "coming" lines (`save.accounts`) now offer sign-in.
