# App size

Part of the decision record. [AGENTS.md](../../AGENTS.md) has the rules that apply to every change and the list of topics. Record decisions about this topic here, in the same change as the code.

- **The Android and iOS apps carry the app, not the website** (Melvin asked why the app doubled in size, 2026-11-11). `npm run build:static` exports everything to `out/`, and Capacitor copied all of it into both shells. By 2026-11-11 that was about 387 MB of files (about 110 MB compressed), and only 27 MB of it was the app: the rest was the public website, mostly the 754 exercise pages and their alternatives pages (275 MB of HTML and Next's page data), the muscle, equipment and blog pages, 25 MB of preview cards (`og/`) and 18 MB of exercise stills (`stills/`). The SEO work and the exercise library batches on 2026-11-11 (#247, #250, #251, #252, #253) added most of it, which is why the bundle jumped in one day. The apps never show those pages: they open straight into `/app/` and link to the website on `SITE_URL` (terms, privacy, share links).
- **How:** `scripts/native-web.mjs` runs after every Capacitor copy (`capacitor:copy:after` in `package.json`, which `npx cap copy` and `npx cap sync` both call, locally, in CI and in `release.yml`) and deletes, from that shell's copy only, every top-level entry of `out/` that isn't on its `KEEP` list: `app/`, `_next/`, `mediapipe/` (camera rep counting's runtime and model), the root `index.html` and `404.html`, the icons, the manifest and `sw.js`. Files Capacitor adds itself (`cordova.js`, `plugins/`) aren't in `out/`, so they stay. `out/` itself is untouched, because the browser tests and the website need all of it. Android and iOS get the same list in the same step. Result: 387 MB down to 27 MB of web files per app (about 11 MB compressed), and the full playthrough passes when served from the trimmed folder.
- **Adding something the app loads by a root path** (a new folder under `public/` that app screens fetch, like `mediapipe/` or `piper/`) means adding it to `KEEP`, or it works on the web and is missing in the apps. Anything new for the website only needs nothing. `src/lib/nativeWeb.test.ts` checks the pruning and the hook; CI's native builds also run when the script changes.
- **Piper Amy** (`public/piper/`, 2026-11-23): the Amy ONNX voice is **committed** under `public/piper/voices/` (~60 MB; like MediaPipe's pose model), with attribution next to it. The phonemizer and ONNX Runtime WASM are copied from lockfile-pinned packages by `scripts/piper.mjs` before each build (gitignored like MediaPipe's runtime). The whole `piper/` folder is kept in both shells so Amy works offline.
- **The camera engine stays in the apps** (Melvin, 2026-11-11: "Keep the camera engine"). Most of what's left is camera rep counting's MediaPipe runtime (14 MB WebAssembly) and pose model (5.6 MB). It stays bundled rather than downloaded on first use, so the camera labs work offline and from the first tap.
- **Code shrinking: R8 on both Android release builds** (2026-11-15, after Play Console's release dashboard for 0.1.0 said "DEX code optimization is below our threshold: Obfuscation (3%)", fix by February 2027, below 25% may hurt visibility). `android/app` and `android/wear` release builds set `minifyEnabled true`, `shrinkResources true` and `proguard-android-optimize.txt`. Capacitor's own consumer rules keep every plugin class and its `@PluginMethod`s (the web layer calls them by name), RevenueCat, Health Connect, Play services and AndroidX bring theirs, and manifest components are kept by AAPT. `proguard-rules.pro` adds: line numbers kept (`SourceFile,LineNumberTable`, source file renamed), our own `com.getliftsmith.app` package kept whole (about 30 small classes, reached by name from the web layer and from Capacitor's reflection), the Garmin Connect IQ SDK (its AAR has no rules and talks to Garmin Connect over AIDL) and Capacitor's Cordova glue. Result in a local release build: 86% of the phone app's classes renamed (5,321 of 6,121) and 88% of the watch app's. **Crash traces stay readable**: the mapping file is packed into the app bundle (`BUNDLE-METADATA`), so Play Console deobfuscates crashes and ANRs with no upload step; there's no native crash reporter in the apps to send it to. CI's Android job builds both release variants too (unsigned), so a missing rule fails the pull request instead of the nightly Release workflow. `src/lib/edgeToEdge.test.ts` checks the settings. If a plugin breaks only in release builds, add a `-keep` for the class it reaches by reflection rather than turning R8 off.
