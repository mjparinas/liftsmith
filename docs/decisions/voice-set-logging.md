# Voice set logging (Melvin, 2026-11-11: Labs idea 4, "say '100 for 8' or 'too easy' to log a set")

Part of the decision record. [AGENTS.md](../../AGENTS.md) has the rules that apply to every change and the list of topics. Record decisions about this topic here, in the same change as the code.

- **A lab** (`labVoiceLog`, off by default, Settings › Labs › Voice set logging; Pro like every lab). While it's on, the workout screen shows a **Say a set** button above Log set (beside Undo when that's showing, `workout/VoiceLog.tsx`). It's an extra way in, never an extra tap: Log set still logs as planned in one tap. Hidden for cardio and once the workout is finished.
- **Push to talk, one utterance.** Tap, speak, and it stops by itself when the lifter stops talking (or after 8 s); tapping again stops it. No always-on listening: the microphone is open only between the tap and the end of the sentence, and it closes when a sheet opens or the app goes to the background (docs/decisions/battery.md).
- **What it understands** (`parseVoice` in `src/lib/voiceLog.ts`, every language tested in `voiceLog.test.ts`):
  - *A set:* "100 for 8", "100 kilos for 8 reps", "100 x 8", "8 reps at 100", "8 reps", or a lone "8" (reps, 1 to 50). It logs straight away, the same way Log set does (burst, sound, PR cue); said during rest it's Log now. Weight is in the gym's unit. Weight alone ("90 kilos") changes the next set without logging.
  - *How it felt:* "too easy", "about right", "too hard" (and "to easy", "2 easy", which recognizers write). When the exercise's how-did-it-feel chip is up, it answers that (exercise feedback, which drives next time's weight); otherwise it fills in the last set's reps left (too easy 4+, about right the plan's, too hard 0). "100 for 8, too easy" does both in one go.
  - *Log it / done* logs the set as it stands; *undo / scratch that* takes back the last set.
  - Recognizers mostly write numbers as digits; small number words (to 20), "a hundred", decimal commas (62,5), full-width digits (Japanese) and "for" heard as "4" ("100 4 8") are handled. The recognizer's five best guesses are read in order and the first that makes sense wins. Phrase lists live in `voiceLog.ts` by language (they're for matching speech, not text the app shows); the lines the app shows are `vl.*` in all six languages.
- **The line under the button says what was heard and what was done** ("Heard “100 for 8”. Logged 100 kg × 8."), so a mishearing is caught straight away and Undo is right there. Misses say what to try. Read out by screen readers (polite live region).
- **On-device only** (2026-11-11). The audio never leaves the phone and nothing is recorded, like camera counting's video. `src/lib/speech.ts` picks the recognizer:
  - *Android:* `SpeechLogPlugin.java`, `SpeechRecognizer.createOnDeviceSpeechRecognizer` (Android 12+, when `isOnDeviceRecognitionAvailable`), with the gym words as biasing strings on Android 13+. `RECORD_AUDIO` is asked for on first use. A phone without an on-device recognizer says so instead of falling back to one that might send audio to a server.
  - *iOS:* `SpeechLogPlugin.swift`, `SFSpeechRecognizer` with `requiresOnDeviceRecognition` and the gym words as `contextualStrings`; music is ducked while it listens. Speech recognition and microphone permission text in `Info.plist` and every `InfoPlist.strings`.
  - *Web:* the Web Speech API with `processLocally` (Chrome 139+), installing the language pack on first use. Browsers that only recognize on a server show "can't recognize speech on the device".
- **Privacy:** no audio, transcript or voice data is stored or sent; only the set it logs is saved, as any set is. So the Play Data safety and App Store privacy answers don't change (audio isn't collected), but the microphone permission now exists on both apps.
- Not yet: hands-free listening (a wake word or listening through rest), and naming an exercise ("bench 100 for 8"). Real-gym accuracy is untested; noise is the risk to watch.
