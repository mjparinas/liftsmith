# Voice and system shortcuts (Melvin, 2026-11-09; built)

Part of the decision record. [AGENTS.md](../../AGENTS.md) has the rules that apply to every change and the list of topics. Record decisions about this topic here, in the same change as the code.

- **Three actions everywhere:** start workout (starts today's plan, or reopens the one running), log set (as planned), and +30 s rest. Log set and +30 s do nothing without a workout, so a stray tap never logs a set nobody did. All entry points run `src/lib/shortcuts.ts`, through the WorkoutSession plugin's `action` event (the same event as the notification buttons), so they behave the same on every platform.
- **iOS** (`ios/App/App/ShortcutIntents.swift`): App Intents plus App Shortcuts, so Siri ("Start a workout in Liftsmith"), Spotlight and the Shortcuts app work with no setup, and the lifter can put any of them on the Action button or in Control Center (iOS 18) as a Shortcut control. The intents open the app (`openAppWhenRun`), because the workout state lives in the web layer.
- **Android:** launcher shortcuts and an App Actions `START_EXERCISE` capability (`res/xml/shortcuts.xml`), and a Quick Settings tile (`WorkoutTileService.java`) that reads "Start workout", or "Log set" while a workout runs. All open `liftsmith://start|log|add30`. Custom App Actions intents for log set were left out, because they need Google's review and the tile and notification already cover it.
- **Web:** the manifest's shortcuts open `/app/?do=start` and `/app/?do=log`.
- **Widgets and controls:** one resizable home-screen widget on each platform (see "Today widget" below; Android `WorkoutWidget.java`, iOS `QuickStartWidget.swift`, which also has lock-screen sizes). iOS has one widget extension target, `ios/App/LiftsmithWidgets` (iOS 16.2+): that widget, the workout Live Activity, and an iOS 18 Control Center control that runs `StartWorkoutIntent`. Widget and Live Activity buttons open `liftsmith://` links, which `SceneDelegate` hands to `ShortcutInbox`.
- Code shared by the app and the extension lives in `ios/App/Shared/` (`WorkoutIntents.swift`: the intents and `ShortcutInbox`; `WorkoutActivity.swift`: the Live Activity attributes). The extension's bundle id is `com.getliftsmith.app.widgets`; release signing creates its profile automatically.
- **Today widget (Melvin chose it, 2026-11-10).** One resizable widget instead of several, so it answers "what should I do today?" without a second control for the same thing. Small: today's call and Start. Medium: adds the one-line why (the same `callWhy` as Today) and, on iOS, the weekly goal. Large (Android 4x3, iOS large): adds the weekly goal ("2 of 4 this week. 2 more keep your 6-week streak.") and the top coach's note with its action ("Fatigue is building · Start a deload"). While a workout runs it says so, and Start becomes Resume with Log set beside it. On a rest day it says why. Tapping the text opens the app on Today, where the full plan and the note's one-tap action are. A live-workout widget was left out: the lock-screen notification and Live Activity already do that.
- **The app builds every line; the widget only draws it.** `src/lib/widget.ts` (`widgetSnapshot`, tested in `widget.test.ts`) makes a small JSON snapshot in the lifter's language from the same data as Today, and `useHomeWidget` (`HomeWidget.ts`, called from `App.tsx`) sends it through `WorkoutSession.setWidget` only when a line changes. Android keeps it in the `liftsmith_widget` shared preferences (excluded from backups like the web view's storage); iOS keeps it in the App Group's defaults. Dismissed coach's notes stay off the widget too. The web app has no browser widgets; its manifest shortcuts stay.
- **Battery: the widget never polls.** `updatePeriodMillis` is 0 and the iOS timeline policy is `.never`. It redraws when the app sends a new snapshot, and once just after midnight (Android: one inexact, non-waking `RTC` alarm; iOS: a second timeline entry), when the snapshot's `day` no longer matches and it says "Open Liftsmith for today's plan." instead of showing yesterday's plan.
- **iOS needs the App Group before it shows the plan.** The extension can only read the snapshot through the App Group `group.com.getliftsmith.app`. Until the App Group capability is added to the App ID and the widgets' ID in the Apple Developer portal, and to both targets' entitlements, the snapshot stays in the app's own container and the iPhone widget shows its plain Start and Log set buttons, as before.
