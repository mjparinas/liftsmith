# Setup wizard (Melvin, 2026-11-09)

Part of the decision record. [AGENTS.md](../../AGENTS.md) has the rules that apply to every change and the list of topics. Record decisions about this topic here, in the same change as the code.

- **A welcome screen comes first** (Melvin, 2026-11-10, after installing the test app on a Galaxy S25+: opening straight onto "What are you training for?" felt jarring). `src/components/app/Welcome.tsx`, one screen, not a swipe-through carousel: the mascot and the name, one line on what the app does, three short points (a plan every day with the reasons, one tap per set, under a minute to set up with no account), **Get started**, and **I already have an account**, which opens the sign-in sheet (sync then brings the lifter's profile back and setup ends). That sign-in button moved here from the goal step, so there is still one control for it (AGENTS.md "One control, one destination"). It shows only on the very first run; "Run setup again" skips it, and Back on the first question returns to it. Pure web code, so Android, iOS and the web app get it together. Analytics records it as `onboarding_step` with step -1, "Welcome".
- First run then opens a short wizard (`src/components/app/Onboarding.tsx`): goal and experience; gym and units; days a week, body weight, and optional age, sex and "I know my numbers" (best recent set of the four main lifts); notifications and a heart rate monitor. Health connections (Health Connect, Apple Health, readiness sources) join it as they land, and should prefill age, body weight and height when the user allows it.
- **It can be run again** from Settings ("Run setup again", `#/setup`). A rerun keeps existing gyms unless the user picks one to add, and never touches workout history.
- One question per screen, big tiles, every step optional except the first three, under a minute in total.
- **The last step before the Pro offer is "Save your progress"** (Melvin, 2026-11-09, after setting up in a phone browser: "it's not clear how to save my information or register"). See "Saving and backup".
