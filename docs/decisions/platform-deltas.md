# Platform deltas

Part of the decision record. [AGENTS.md](../../AGENTS.md) has the rules that apply to every change and the list of topics. Record decisions about this topic here, in the same change as the code.

Every place where Android, iOS and the web app differ, and why. Keep this table current, and update it in the same change as the feature.

| Feature | Android | iOS | Web app | Why |
| --- | --- | --- | --- | --- |
| Lock-screen workout | Ongoing foreground-service notification, promoted as a Live Update on Android 16 (status bar chip and text with the rest time left or the set, a rest bar while resting and a workout progress bar otherwise; Samsung One UI 8 shows it in the Now Bar) | Live Activity (lock screen, Dynamic Island with the countdown, "Rest over" or the set, rest bar while resting, workout progress bar) plus a rest-over notification, kept because a Live Activity can't sound on its own; Android says rest over in its live card instead | Service-worker notification and an alert while the page is open; no chip or progress bar | Each platform's own mechanism; browsers have no live or status bar notifications |
| Watch app | Wear OS 3+ app: the workout, rest countdown, Log set and +30 s, heart rate from the watch's sensor, a buzz when rest ends, opened by the phone when a workout starts (`RemoteActivityHelper`) | Apple Watch app (watchOS 10+): the same, with a strength training workout session for heart rate, opened by `startWatchApp` | None | Browsers can't reach a watch |
| Quick toggle | Quick Settings tile | Control Center control (iOS 18+) or a Shortcut control | None | No browser equivalent |
| Widgets | Resizable Today widget: call and why, weekly goal, coach's note, Start / Log set | Same widget plus lock-screen sizes, but it shows the plan only once the App Group `group.com.getliftsmith.app` is set up in the Apple portal; until then, plain Start and Log set | Manifest shortcuts | No browser widgets; iOS widgets can only read app data through an App Group |
| Voice | App Actions, start workout only | Siri and App Shortcuts, all three actions | None | Custom App Actions intents need Google's review |
| Calendar | Read and write | Read and write | `.ics` download, no busy times | Browsers can't reach the calendar |
| AirPods Pro heart rate | None | Yes (planned) | None | Apple only |
| Desktop layout (sidebar, wide pages, sheets as centred dialogs) | None: phones and tablets keep the phone layout | None: phones and tablets keep the phone layout | On a window 1,024 px+ wide with a mouse or trackpad | Melvin, 2026-11-12: "tablets should keep the phone layout for now"; see [Desktop layout](desktop-layout.md) |
| Volume follows intensity | Yes (planned extra) | None | None | iOS can't set system volume or control other apps. It was skipped before; it can come back as an Android extra |
| Samsung Health | Through Health Connect (a line on the Health Connect card says how to share); no direct Data SDK link (partner approval, nothing extra) | None (Samsung Health on iPhone doesn't share) | None | Samsung devices only |
| Garmin watch app | Paired watches found through Garmin Connect | The lifter picks the watch once in Garmin Connect (iOS apps can't ask for the list) | None (a page can't reach a Garmin watch) | Garmin's companion SDKs differ per platform |
| Date of birth and sex | Asked in the app | From Apple Health | Asked in the app | Health Connect has neither |
| Fitbit Air data | Health Connect | Apple Health, one way only | None | Fitbit syncs to Apple Health one way |
| Friends push notifications | Firebase Cloud Messaging, once `GOOGLE_SERVICES_JSON` and `FCM_SERVICE_ACCOUNT_JSON` are set | APNs, once the push capability and key are set up (deferred) | None: the people button's dot and Activity | Web push would need a service worker push subscription and VAPID keys; the app's own screens already show the dot |
| Cheers during a workout | Float up the workout screen; a push (Cheers switch) when the app is in the background, mirrored to Wear OS | The same; the push mirrors to Apple Watch (once APNs is set up) | Float up the workout screen, read every 30 s while it's on screen; no push | Same as Friends push notifications |
| Health data | Health Connect | Apple Health | None | Browsers have no health store |
| Health twin | All metrics from Health Connect (HRV is RMSSD); fitness age from its VO₂ max | All metrics from Apple Health (HRV is SDNN, so values run higher; only the lifter's own trend is used); fitness age from its VO₂ max | Weigh-ins, body fat, BMI, TDEE and the rest-time heart rate drop (Web Bluetooth); health-store metrics and fitness age say "On your phone" | Browsers have no health store |
| Bluetooth heart rate | Yes; the last monitor reconnects by address without a scan | Yes; the last monitor reconnects by its iOS id without a scan | Web Bluetooth, Chrome only; reconnects without the picker only where the browser keeps the permission (`getDevices`) | Browser support |
| Bluetooth smart scale (Labs) | Yes (Weight Scale and Body Composition services through the Bluetooth plugin) | Yes, the same | Web Bluetooth, Chrome only | Browser support |
| Bluetooth gym machines (Labs) | Yes (FTMS through the Bluetooth plugin); reconnects to the same machine after a drop | Yes, the same | Web Bluetooth, Chrome only; after a drop it reconnects only where the browser keeps the permission (`getDevices`), otherwise the lifter taps Connect machine | Browser support |
| Gym by location | Yes | Yes | None | No geofence in the web app |
| Voice coach | System TextToSpeech; the rest-over cue is said by the workout service, so it's heard with the screen locked | AVSpeechSynthesizer while the app is open (screen stays on in a workout); locked screen gets the rest-over notification only | Web Speech API while the page is open | iOS suspends background apps, so it can't speak from the lock screen without an audio session we don't keep |
| Earned app icons | Launcher activity-aliases, switched when the app goes to the background | Alternate app icons (iOS shows its own "icon changed" alert) | None | Browsers can't change a home-screen icon |
| Friends invite links | App Links open the app; without it, Google Play keeps the invite as the install referrer | Opens the web app (Universal Links deferred, no install referrer); after installing, open the link again | The web app does it all | iOS can't carry a link through the App Store install |
| Friends club links | App Links open the app (the same `/app` filter as invites) | Opens the web app (Universal Links deferred); joining there joins on every device | The web app does it all | Same as invite links |
| Buddy check-in | Share sheet | Share sheet | Web Share, else copied to the clipboard | No in-app delivery: accounts have no friends list |
| Reminder notifications | Local notifications on a "Reminders" channel | Local notifications | Email only | Browsers can't schedule a notification while the page is closed without a push server; email covers the web |
| Camera rep counting | MediaPipe in the web view (CAMERA permission) | MediaPipe in the web view (`NSCameraUsageDescription`) | Same, any browser with a camera | One code path for now; native ML Kit / Vision only if on-device tests show the web view is too slow |
| Voice set logging (Labs, `labVoiceLog`) | On-device `SpeechRecognizer`, Android 12+ phones that have one (`RECORD_AUDIO`) | `SFSpeechRecognizer` with on-device recognition only (`NSSpeechRecognitionUsageDescription`, `NSMicrophoneUsageDescription`) | Web Speech API with `processLocally`, Chrome 139+ only | Audio must stay on the device, so phones and browsers without an on-device recognizer say so instead |
| Volume button logs a set (Labs, `labVolumeLog`) | Phone's volume up key (`dispatchKeyEvent`) and earbuds through the music volume, while the app is on screen | Audio session volume (phone buttons and earbuds), set back with a hidden volume slider, while the app is in front | None | Browsers don't give pages volume keys; neither phone gives a backgrounded app its volume presses |
| Now playing (music controls) | Any music app through the phone's media keys; song names and direct control after notification access (`NowPlayingPlugin.java`, `MediaListener`) | Apple Music only (`MPMusicPlayerController.systemMusicPlayer`, after the lifter allows Apple Music) | None | iOS gives apps no way to read or control another app's playback, so Spotify and the rest are controlled from Control Centre on iPhone; a web page can't reach other apps' music |
| Motion rep counting (Labs, `repMotion` flag, off) | DeviceMotionEvent (fused linear acceleration and gyro) | DeviceMotionEvent after a permission prompt (`NSMotionUsageDescription`) | Phones only | Watch apps (Wear OS, watchOS) would feed the same counter later |
| Watch rep counting (Labs, `labWatchReps`) | The Wear OS app streams linear acceleration, gravity and gyroscope at 50 Hz during a set (`MotionStream`); needs the watch's heart rate permission, because the streaming runs in its workout service | The Apple Watch app streams Core Motion device motion at 50 Hz during a set, inside its workout session | Not offered (no watch app); the lab is hidden on the web | Both phones count with the same web code (`watchMotion.ts`). Garmin isn't included: Connect IQ messages are too small and slow for 50 readings a second |
| Per-app language | System per-app language on Android 13+ (in-app choice below that for the app, phone language for notifications) | System per-app language in Settings › Liftsmith (the widget, Live Activity, rest-over alert and Siri phrases are native text in `.strings` files and follow the phone's language) | Browser language | Each platform's own language setting; Settings › Language overrides it everywhere |
| Rest-over alert choice (sound, vibration, both, silent) | All four exactly: the live card itself says "Rest over" (no second notification, 2026-11-12), and the workout service plays the phone's notification sound (ringer on, Do Not Disturb off) and buzzes, or not, as picked | Sound or silent on the lock screen; "vibration only" posts a silent banner and buzzes in the app when it's open | Notification sound and vibration pattern while the page is open | iOS can't vibrate a local notification without its sound, and Android channel settings can't change once made |
| Pro subscription | Google Play Billing (through RevenueCat) | StoreKit (through RevenueCat) | Stripe Checkout and Stripe's customer portal, for a signed-in account only (until Stripe is set up: nothing to buy, everything unlocked) | The stores require their own billing in the apps, and don't allow pointing to another way to pay, so a phone shows a web subscription's status as plain text with no link. Pro from any of the three follows the account to the others (`src/server/access.ts`) |
| Saving your data | Saved in the app's own storage until uninstall, and kept out of Google's backup and phone-to-phone transfer | Same, and kept out of iCloud and computer backups | Saved in the browser's storage, which clearing site data, a private window or Safari's 7-day rule can erase; the app asks the browser to keep it and offers Add to home screen | Browsers can clear site storage; the native apps own theirs. Accounts and sync will cover all three |
| Sign-in | Google (Credential Manager) and an emailed code | Apple and Google (AuthenticationServices) and an emailed code | Google (Google Identity Services), Apple (Sign in with Apple JS) and an emailed code | Apple only requires Sign in with Apple on iOS; on Android it would need a web redirect flow, and an Apple user can use the emailed code with the same address |
| Shared links (workout remix, shared routines) | Opens in the installed app (verified App Links on `www.getliftsmith.com/app`, `src/lib/appLinks.ts`) | Opens in the browser app; Routines › Add a routine from a link takes a pasted routine link | Opens in the app | Universal Links need the Associated Domains entitlement and `apple-app-site-association` (iOS deferred, Open items) |
| Creator codes | Arrive with the install from the link's Play badge (install referrer), or typed | Typed in setup's trial step or Settings, because the App Store passes nothing per install | Saved by the link page on the same site, or typed | Apple has no per-install referrer for ordinary installs |
| Script policy (security) | None | None | Each page allows only our own files, its own hashed inline scripts and the Google and Apple sign-in libraries (`scripts/csp.mjs`) | On Android WebViews without document-start scripts, Capacitor puts its bridge into the page as an inline script whose hash we can't know, so a policy could stop the app from starting; the apps only load their own files |
| Back | The system back button and back gesture: close an open sheet or dialog, else the previous screen, and only on Today send the app to the background (`@capacitor/app` `backButton`, `src/lib/back.ts`) | Swipe in from the left edge goes to the previous screen (`allowsBackForwardNavigationGestures`); a sheet closes with ✕ or a swipe down | The browser's back button goes to the previous screen | iOS has no back button; its edge swipe moves through the same history, and a sheet on the screen goes with it |
| Connected apps › Health | Status, which reads and writes were allowed, Sync now, Change permissions (opens Health Connect's own screen, or its Play listing when it isn't installed) | Status from writes and the last sync, Sync now, and a line on where to change it (Health app › Apps › Liftsmith) | Says Health is in the phone apps | HealthKit never tells an app which reads were allowed and has no screen an app can open |
| Strava, Oura, WHOOP, Withings, Polar, Concept2 | Through the account and our server; sign-in opens the browser and comes back by `liftsmith://connected` | Same | Same; the sign-in page comes back to `/app/#/connections` | One server path for all of them |
| Rest countdown ticks (last 3 s) | The workout service vibrates three light ticks itself, so they're felt with the screen locked or the phone in a pocket | Light haptic ticks while the app is open; the locked phone gets the rest-over notification only | `navigator.vibrate` ticks while the page is open (Android browsers) | iOS can't vibrate from the background without a notification, and three notifications in three seconds would be noise |
| Workouts in the health store | Strength training exercise session with title and sets as notes; calories and heart rate as separate records | Traditional strength training workout with calories and heart rate inside it; title only (no notes field) | None | Each store's own workout model |
| Your stats from health data | Height (and weigh-ins with body fat) from Health Connect; age and sex are entered in Your stats, with a line saying why | Height, sex and date of birth from Apple Health (`HealthWorkoutPlugin.swift` `characteristics`), plus weigh-ins with body fat | Entered in Your stats | Health Connect has no records for sex or date of birth; HealthKit keeps both as characteristics |
| Coaching messages and alerts | A push for each new message, a client's finished workout and a client gone quiet for a week (FCM, `notifyCoach`) | Same through APNs | No push: new messages show as counts on Coaching and a card on Today, and an open chat checks every 20 seconds | The web app has no push; the phones register their token with the coaching server on their own, so this works without Friends |
