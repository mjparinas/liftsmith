# Calendar (Melvin, 2026-11-09, roadmap MVP+2; built)

Part of the decision record. [AGENTS.md](../../AGENTS.md) has the rules that apply to every change and the list of topics. Record decisions about this topic here, in the same change as the code.

- **Settings › Training › Schedule** (`CalendarSettings.tsx`, `src/lib/calendar.ts`; was Settings › Calendar until 2026-11-10): pick training weekdays, which also set the days-a-week goal (`trainingDays`, docs/decisions/settings-screen.md), (defaults spread the days-a-week goal, 3 → Mon, Wed, Fri) and a time, then **Add to my calendar**. That writes one weekly repeating event (the workout length) to the default calendar, and Update or Remove replace or delete it by its saved id. The web build downloads a `.ics` file instead.
- **Which calendar, and where to look** (Melvin, 2026-11-12: "the button changes to update my calendar but i dont see it anywhere"). Android used to write to the first writable calendar the phone listed, which on many phones is a phone-only one (Samsung's "My calendar", a local account) that Google Calendar never shows. It now ranks them (`CalendarPick.score`): a Google account's primary calendar, then any account's primary calendar, then any synced calendar, phone-only calendars last, and asks that account to sync right away. iOS keeps the default calendar for new events (the one the lifter picked in Settings). After saving, both say which calendar it went into and when the first one is ("Added to your … calendar. The first one is Wednesday, November 11 at 6:00 PM."), with **Show in my calendar** opening the calendar app at that day (Android `content://com.android.calendar/time/<ms>`, iOS `calshow:`).
- **The time is set on a clock dial** (Melvin, 2026-11-11: "i dont like the clock control that pops up … make it a popup like on android and let you set the hour and minutes on a click dial"). The row's one button shows the time and opens a sheet (`TimeField` in `TimeDial.tsx`, math in `src/lib/timeDial.ts`): tap or drag round the face for the hour, and it moves on to the minutes by itself, in fives; the big readout switches between hour and minutes, AM / PM sit beside it where the region uses them (from Intl), and a 24-hour region gets Android's two rings (00 to 11 outside, 12 to 23 inside). **Set time** saves; ✕, a swipe down, Escape or back leave it as it was. The numbers are buttons too, so keyboards and screen readers pick them. It replaced the browser's own `<input type="time">`; pure web code, so Android, iOS and the web get the same dial.
- **Fit workouts around my calendar** is a separate opt-in (native only). When it's on and nothing is running, Today reads busy times for the next 3 hours every 5 minutes. If something starts before the planned workout could finish, it offers a shorter length that fits ("Busy at 7:00 pm · Fit a 30-minute workout"): the free time less 10 minutes, rounded down to 5, at least 15 (`fitLength`).
- **Privacy:** only start and end times are read. Titles, places, attendees and notes are never read. All-day events, events marked free and Liftsmith's own event are ignored, and nothing leaves the phone.
- Native: `CalendarPlugin.java` (CalendarContract, `READ_CALENDAR` + `WRITE_CALENDAR`) and `CalendarPlugin.swift` (EventKit, full access on iOS 17+, because updating our own event and reading busy times both need reads). The same JS drives both (parity).
