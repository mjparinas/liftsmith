# Web dashboard (Melvin, 2026-11-09: "a website for users as well, similar to Hevy")

Part of the decision record. [AGENTS.md](../../AGENTS.md) has the rules that apply to every change and the list of topics. Record decisions about this topic here, in the same change as the code.

- **Retired into the app** (Melvin, 2026-11-12: "fold me into app and retire it"; [Desktop layout](desktop-layout.md), stage 2). The web app at `/app/` has a desktop layout of its own now, so a second big-screen page only split the web in two (sign-in in one, the big view in the other). `/me/` is now `MeRedirect`, which sends old links and bookmarks into the app: `#/log` to Log a past workout, `#/friends` to Friends, `#/trophies` to Awards, everything else to Progress. The dashboard's code (`Dashboard.tsx`, `Charts.tsx`) and its text are gone.
- What moved and where:
  - **Log a past workout** is an app screen (`#/log`, `LogPast.tsx`) on every platform, opened from Progress under the history calendar. It writes the same events as before (`pastWorkoutEvents`, `source: "manual"`) but through the store (`importWorkouts`), so stats update at once and sync sends it on. Numbers are bump fields and exercises come from the exercise browser, rather than the dashboard's text boxes and a 1,000-item list.
  - **Friends** (feed beside challenges and the board) is the app's Friends screen on the desktop layout; `#/friends` goes there ([Friends](friends.md)).
  - Overview, calendar, history, bests, PRs and trophies were already in the app (Progress, the history calendar, the exercise pages and Awards). One-rep max trends are on each exercise page.
  - The year heatmap and the workouts-a-week bars were dropped: they're stats for their own sake (AGENTS.md: action over stats).
  - **Share summary links** (`/share/#…`): no new ones are made (the app's share sheet and public links replaced them), but `/share/` still opens the ones already sent (`SharedProfile` in `src/components/dashboard/Share.tsx`).
- `/me/` and `/share/` stay `noindex` and disallowed in `robots.txt`.

## History (before 2026-11-12)

- Hevy's site is a big-screen view (routines, exercise progress, friends' workouts), and its feature guide says workouts can be logged from a browser; past workouts can be added by hand. Ours matches that: the full app already runs in a browser at `/app/` (live logging), and `/me/` is a desktop dashboard (`src/components/dashboard/`, views in `src/lib/dashboard.ts`).
- Tabs (hash routes `#/overview`, `#/calendar`, `#/lifts`, `#/history/<session>`, `#/trophies`, `#/log`, `#/share`): level and totals, workouts a week, a year heatmap and a month calendar of training days, one-rep max trends and bests by exercise, weekly sets per muscle, every set of every workout, trophies, **log a past workout**, and a share link. It is a website page, linked from the site footer ("Your dashboard"). The app has no link to it (Melvin, 2026-11-10: the Settings button "Open the big-screen dashboard" felt out of place in the phone app and was removed on Android, iOS and the web app alike).
- **It reads the same on-device event log** as the app, so it shows the workouts saved in that browser or app; signing in to the web app (`/app/` › Settings › Account and sync) syncs the phone's workouts into that browser, and the dashboard shows them. The dashboard has no data path of its own.
- **Past workouts** are written as the same events a live workout writes, with `source: "manual"` on the `sessionStart`, sets spread across the workout, what was lifted taken as the target (so progression counts it as hit) and RIR 2 assumed for recovery. No editing or deleting yet: deletes need sync tombstones.
- **Free vs Pro** (`src/lib/entitlements.ts`, `can("advancedStats")`): overview, calendar, history, bests, PRs, trophies, past-workout logging and sharing are free; one-rep max trends and weekly sets per muscle are Pro, like the app's advanced stats (gated in the app too since 2026-11-12, [Money](money.md)). `isPro()` is always true until billing lands; then a running trial counts as Pro.
- **Sharing before accounts:** `/share/#<summary>`. The summary lives in the link's fragment, which browsers never send to a server, so nothing is uploaded. It holds level and XP, workouts, goal streak, trophy ids, the top five estimated one-rep maxes and which of the last 84 days had a workout; the name only when the lifter ticks it. **Never** heart rate, body weight, cycle data, gyms or locations. `decodeShare` validates every field and rejects anything unknown. Following friends and a shared feed wait for accounts.
- `/me/` and `/share/` are `noindex`. The heatmap squares are pointer-only (too small to tap); keyboard and screen reader users get the same days from the month calendar.
- **Friends tab** (Melvin, 2026-11-12, Friends gap list 3 item 8): the feed (Following or Discover) beside challenges and this week's board, using the app's own Friends components; profiles, joining, people and settings open in the web app. Moved into the app with the rest; see [Friends](friends.md) under "Friends on a big screen".
