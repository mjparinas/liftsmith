# Set timer for holds, carries and hangs

Part of the decision record. [AGENTS.md](../../AGENTS.md) has the rules that apply to every change and the list of topics. Record decisions about this topic here, in the same change as the code.

- **Why** (Melvin, 2026-11-12: "For some exercises that require a length of time, can you add a timer functionality"). Holds, carries, hangs and timed drills were already planned and logged in seconds (`TIMED` in `progression.ts`: plank, side plank, dead hang, wall sit, farmer's carry and about 180 more, cardio included), but the lifter had to time them on another clock and then dial the seconds in.
- **What it does** (`src/lib/setTimer.ts`, pure and tested; `workout/SetTimer.tsx`). On any `TIMED` exercise a **Start timer · 0:40** button sits above Log set (free, not a lab). One tap starts a **5-second lead-in** ("Get set") to get into position, then the set **counts down** from the seconds dialled in, in a big clock in the button's place, with a bar and "Log set saves 0:12". When it runs out **the set logs itself** at the moment it ended, so the rest timer starts as after any set: a plank is one tap, not two, and Undo takes it back. **Log set while it runs saves the seconds actually held** (during the lead-in it logs the set as planned). **Cancel** stops it without logging.
- **Each side** (`perSide`, e.g. side plank, bottoms-up kettlebell hold, split squat hold; carries and one-sided holds like the suitcase carry are one timed set, not per side, Melvin 2026-11-12): "Start timer · 0:20 a side" counts the first side, gives 5 s to switch ("Switch sides"), then counts the second. Stopping on the second side logs the first side's full time and the second side's own (`repsL`/`repsR`, as when the sides differ).
- **Cardio counts up** ("Start the clock"), because its target is only last time's, to repeat or beat: it chimes once on passing the target, keeps going, and Log set saves the time. It never logs itself.
- **Sound, touch and voice** follow the Sounds and Vibration switches: a tick on the last three seconds of the lead-in, the switch and the hold, the rest-over chime and a thud on go, a goal chime when cardio passes its target. The voice coach (when on) says "Ten seconds" on holds of 20 s or more and "Switch sides". Text is `timer.*` in all six languages.
- **The clock is wall time**, kept outside the screen (`startTimer`/`takeTimer` in `SetTimer.tsx`), so going to Today and back mid-hold keeps it, and a hold that ran out while the app was in the background logs at the moment it ended, without late beeps. It belongs to one set; once that set is logged it's gone.
- **Lock screen and watches** (Melvin, 2026-11-12: "can you add this to the lock screen and watch"). The app sends the running timer with each live update as phases in wall-clock time (`timer`, `TimerSegment[]` in `sessionNotify.ts`, from `timerPhases` and labelled by `sessionTimer`: "Get set", "Time left" or "First side", "Switch sides", "Second side", or "Target 20:00" for cardio's count-up) plus `timerOver` ("Time's up"). Every surface picks the phase that has started and not ended (the same rule as `timerSegmentAt`) and counts it on its own clock, so it keeps going with the phone locked and the app asleep. Nothing shows while resting.
  - *Android notification* (`TimerPhases.java`, `WorkoutService`): "Time left 0:23" in the card and its text, the time in the Live Update chip and Now Bar, and a bar through the phase; redrawn once a second only while the timer runs. A buzz as each phase ends (go, switch sides), and when the hold is over the card says "Time's up" with the rest-over sound and buzz (the lifter's rest-over alert setting) until the app logs the set. A Log set from the card with the app closed leaves the timer behind.
  - *iOS Live Activity* (`TimerPhase` in `Shared/WorkoutActivity.swift`, `WorkoutLiveActivity.swift`): the label in place of the set, the system-ticked countdown (or count-up) on the lock screen and in the Dynamic Island, and a bar through the phase. It goes stale at the next phase change, so the system redraws it then. The hold's end is a time-sensitive alert in the rest-over slot ("Time's up", with Log set), since a Live Activity can't sound by itself.
  - *Wear OS and Apple Watch* (`WorkoutState.phase`, `WatchState.phase`): the clock big with its label under it, and a buzz or tap as each phase ends.
  - *Garmin* (`"k"` in `GarminMessages`, seconds from now like rest, so the two clocks never have to agree; `"ki"` says which timer it is so a running one isn't resent every second): the clock with its label, and a buzz as each phase ends.
  - *Web:* browser notifications can't count down, so the web app shows it on the page only.
- **Platforms:** the timer itself is web code, so Android, iOS and the web app get it together; the lock screen and the watches are native on both phones and all three watches. The screen stays on during a workout by default, which covers a phone on the floor beside a plank.
- **Not built yet:** starting the timer from the lock screen or a watch (it starts on the phone), and a timer on warm-ups (timed exercises have none). The iOS Live Activity redraws by itself only at its next phase change, so after "Switch sides" its second side's countdown relies on that one redraw.
